## Context

当前项目是一个基于 Wails 的局域网文件共享桌面应用：
- 后端：Go + HTTP Server（端口 8765）
- 前端：Vue 3（共享者桌面界面）+ 原生 HTML（访问者网页）
- 窗口尺寸：400x400（固定）
- 现有功能：文件共享、二维码分享、拖拽上传

需要新增消息公告板功能，保持界面改动最小化。

## Goals / Non-Goals

**Goals:**
- 实现双向消息发送（共享者 ↔ 访问者）
- 消息存储在内存中，最多50条
- 访问者身份默认内网IP，可自定义名字
- 界面仅新增图标按钮，弹窗展示消息
- 轮询刷新消息（每3秒）

**Non-Goals:**
- 不做消息持久化（重启清空）
- 不做实时推送（WebSocket）
- 不做消息编辑/删除单条
- 不做已读/未读状态追踪
- 不改变窗口尺寸

## Decisions

### 1. 消息存储方式
**决定**：内存存储（App.messages []Message）
**原因**：
- 简单，无需文件IO
- 重启清空符合"临时公告"定位
- 访问者刷新可通过API获取

**备选**：存到共享目录 .message 文件
- 优点：重启保留
- 缺点：需要文件读写，访问者刷新也能看到（但需要额外处理）
- 结论：用户明确要求内存存储

### 2. 实时性方案
**决定**：轮询刷新（每3秒）
**原因**：
- 实现简单，无需 WebSocket
- 3秒延迟可接受
- 不增加复杂度

**备选**：WebSocket 实时推送
- 优点：真正实时
- 缺点：需要升级 HTTP Server，复杂度大增
- 结论：超出项目简洁定位

### 3. 访问者身份标识
**决定**：默认内网IP，可自定义名字
**原因**：
- IP 自动获取，无需用户操作
- 自定义名字满足个性化需求
- 名字存 localStorage，刷新保留

**实现**：
- 新增 /api/myip 接口返回访问者IP
- 访问者网页显示名字输入框（可选）
- 发送消息时带上名字或IP

### 4. 界面交互方式
**决定**：图标按钮 + 弹窗对话框
**原因**：
- 界面改动最小化（仅新增一个图标）
- 弹窗不占用主界面空间
- 符合用户明确要求

**实现**：
- 头部右侧新增 💬 图标
- 图标显示未读角标（消息数量）
- 点击弹出模态对话框
- 对话框：消息列表 + 发送框 + 清空按钮

### 5. API 设计
**决定**：RESTful API
- GET /api/messages - 获取所有消息
- POST /api/message - 发送消息
- GET /api/myip - 获取访问者IP

**原因**：
- 与现有 API 风格一致
- 简单直接

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 内存存储重启丢失 | 明确告知用户，符合"临时公告"定位 |
| 轮询有延迟 | 3秒延迟可接受，后续可优化 |
| 多访问者同名 | 显示 IP 区分，如 "小王(192.168.1.100)" |
| 消息过多内存溢出 | 限制最多50条，超出删除最早的 |
